# 北欧 Data Engineer 面试指南：流程、文化题与技术深挖题

北欧数据工程岗位（Data Engineer）面试与国内最根本的区别：**他们面的是「你能不能跟我们一起舒服地工作」，而不只是「你能不能干活」。** 技术是入场券，文化契合决定录用结果。

本文基于真实北欧招聘流程资料（详见文末来源），按「流程 → 文化题 → 技术题 → 反问 → 准备清单」拆解。

## 一、北欧面试流程：一般 3~5 轮 + 推荐人核查

| 轮次 | 谁面 | 时长 | 考察什么 |
| --- | --- | --- | --- |
| **0. 材料筛选** | HR | — | 简历 + 求职信。HR 先看**文化契合信号**：求职信是否具体提到公司、语气是否克制真诚 |
| **1. 初筛** | HR / Recruiter（常远程） | 30-45 min | 资质核对、动机、**薪资范围粗探**（会直接问期望区间）、搬迁/工作许可意愿 |
| **2. 经理面（最重）** | 未来直属经理 | 60-90 min | **技术深度 + 行为例证**，盯着简历上的项目追问细节，验证真实做过 |
| **2.5. 技术评估** | 视公司而定 | take-home 可能给**一周**，或现场 SQL / 系统设计 | 北欧公司普遍信「做一遍」胜过「说一遍」 |
| **3. 团队面** | 1-3 位未来同事 | 45-60 min | **文化契合、协作方式**。技术已被认可，这轮考「能不能跟我们舒服地工作」 |
| **4. 终面（可选）** | 团队负责人 | — | 高级岗常见，方向性判断 |
| **推荐人核查** | 前雇主 / 推荐人 | **有条件录用后**启动 | 轻量验证，多数只确认**任职日期与职位头衔**，约 5-10 个工作日 |
| **Offer** | HR | — | 薪资对话（lönesamtal）在最后，用数据谈 |

**时间线**：中级岗 6-12 周，高级岗 8-16 周以上。北欧是共识决策，**慢是常态**，催进度反而减分。全程你会面到 4-8 个人，人人都有否决权。

**关于背调（reference check）**：北欧是「信任为基础」的雇佣文化，背调比你想象中轻——多数公司只在**有条件录用（conditional offer）发出后**做基本核实，且受瑞典隐私文化影响，前雇主通常只确认**任职日期和职位头衔**，不做深入访谈。针对中国候选人：公司一般通过**邮件/书面形式**联系你的推荐人核实雇佣记录，或委托 HireRight、Deel 等全球背调机构自动化处理（数分钟出结果）。语言障碍和渠道不熟悉是国际公司公认的难点，所以提前和推荐人打招呼、确认他们会回复邮件就够了——深度电话访谈式背调在中国背景候选人身上并不常见。

## 二、文化契合题（第 1、3 轮，陷阱最多）

- **「你为什么想来北欧？为什么是我们公司？」**——考察动机真实性。别答「福利好」，要具体到公司的产品/技术。
- **「你理想的工作生活平衡是什么样？」**——陷阱题。回答透露「可以随时加班」会直接出局。
- **「你通常怎么给同事提建设性反馈？被批评时什么反应？」**——北欧是直接反馈文化，他们想确认你接得住直球。
- **「讲一个你和团队意见分歧的项目。」**——詹特法则测试：期待你用「我们」叙事，承认他人贡献。
- **「你最大的缺点？」**——诚实具体，别背「我太完美主义」这种标准答案。

## 三、Data Engineer 技术深挖题（第 2 轮，会追到细节）

> **说明**：本节为基于数据工程岗位通用经验与本候选人简历的**合理预判**，非文献引用——面试官具体问什么取决于公司与聊到的项目，仅供准备参考，请勿当作标准题库。

面试官会拿着简历逐条追问，数字背后的「怎么做」比数字本身重要。以下按 DE 岗位核心能力拆成五类：

### 1. 数仓建模

- 你做过哪些层（DWD/DWS/ADS）？各层设计取舍是什么？
- **为什么退化维度属性？** 什么时候该退化、什么时候不该？
- 事实表设计：事务事实表 vs 周期快照表 vs 累积快照表，怎么选？
- 指标口径不一致你具体怎么治理的？「减少了 50%」**怎么度量**？

### 2. 数据治理与质量

- 数据倾斜怎么定位热点 key？加盐、广播、还是重分区？效果怎么验证？
- DQC 规则你设计过哪些类型（完整性/一致性/及时性）？超时率从 10% 降到 0，靠的是规则还是调度？
- 布隆过滤器方案：误判率怎么设？**假阳性对下游的影响怎么兜底**？为什么选它而不是增量快照对比？
- 存储成本下降 ~40%，大头来自哪一项？怎么量化验证的？

### 3. 实时计算（Flink）

- 双流 join 的**乱序和迟到数据**怎么处理？watermark / allowedLateness 怎么设？
- Flink 状态大小怎么控制？checkpoint 策略？
- 为什么选 FlinkSQL 而不是 Flink DataStream API？权衡是什么？
- 实时看板「秒级准确」怎么保证？对账机制是什么？

### 4. 数据湖与批流一体

- **为什么选 Delta Lake 而不是 Hudi / Iceberg？** upsert 的 merge 代价是什么？
- 存算分离省了多少资源？你是怎么衡量的？
- 湖 vs 仓 vs Lakehouse 你怎么看？什么时候用哪个？

### 5. 迁移与平台

- 600+ 调度任务无中断迁移：**双跑怎么做的？数据一致性怎么对账？回滚方案是什么？**
- DataWorks vs Databricks 的差异，你更习惯哪个？
- 调度依赖、基线告警体系你搭过吗？

## 四、场景 / 案例题（2.5 轮）

- **现场系统设计**：给你一个电商场景设计实时看板（先想好通用框架：数据接入 → 实时清洗 → 双流关联 → 聚合 → 输出 → 对账）
- **SQL 优化题**：一段慢 SQL，现场说优化思路（先 explain，再看 join 顺序、倾斜、谓词下推、文件大小）
- **数据质量 case**：业务说指标对不上，你怎么排查？（口径 → 链路 → 数据 → 代码，四层定位法）
- **take-home 题**：通常是一周内完成的小项目（写一个 ETL 或优化脚本），**注重可读性、注释和 README**，北欧公司会认真读你的代码风格

## 五、你该反问的（北欧面试官把这当重点）

- 「团队日常怎么做决策？共识制还是有人主导？」
- 「数据团队现在最大的技术债是什么？」
- 「这个岗位前 6 个月的成功标准是什么？」
- 「公司如何处理繁忙期的数据延迟与工作生活平衡？」

好的反问展示你对协作方式的理解——这在北欧比「你司用啥技术栈」加分得多。

## 六、准备清单

1. **把核心项目练成 2 分钟 STAR 版**（背景 → 方案 → 结果，全程用「我们」），这是被问概率最高的素材
2. **准备 1-2 个推荐人 + 前公司 HR 联系方式**——北欧背调多为轻量「雇佣验证」，书面/邮件确认**任职日期与职位头衔**，提前打好招呼让他们会回邮件
3. **背好你的数字**：~40% 存储、10%→0、3天→1天、600+ 任务——每个数字背后都要能讲出「怎么做到的」
4. **过一遍通用题库**：建模分层、Spark 调优、Flink watermark、湖仓选型，至少能说 2-3 分钟
5. **练英语技术表达**：能流畅用英文讲清「数据倾斜怎么解决」，比背一堆技术名词有用

## 七、心态：这是一场相互评估

北欧面试的底层逻辑是平等——你在被评估，也在评估公司。带着「我看看你们适不适合我」的对等心态进场，本身就是最符合北欧价值观的姿态。
